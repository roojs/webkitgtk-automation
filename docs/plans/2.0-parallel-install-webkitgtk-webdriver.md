# 2.0 — Parallel-install WebKitGTK WebDriver build

**Status:** ⏳ proposed — approve before implement  

**Repo:** this repository (`webkitgtk-automation`)  
**Unblocks:** ollmchat / libocwebkit as a normal dependency without replacing system `libwebkitgtk-6.0`  
**Depends on:** Phase 1 (1.0) — GTK4-only rebuild with `ENABLE_WEBDRIVER=ON`  
**Upstream bug:** [WebKit #318171](https://bugs.webkit.org/show_bug.cgi?id=318171)

---

## Purpose

- 🔷 Ship a **second** WebKitGTK 6.0 stack (runtime libs + helpers) that can sit **next to** Ubuntu’s `libwebkitgtk-6.0-4`.
- 🔷 Keep the **same C API / Vala vapi** as `webkitgtk-6.0` — only the **shared libraries**, **libexec helpers**, and **pkg-config names** differ.
- 🔷 Let ollmchat (and other Meson consumers) select the WebDriver-enabled stack via `dependency('…')` / a Meson option, without forking application code.
- 🔷 Retire the Phase 1 “replacement `.deb`” story (`libwebkitgtk-6.0-4` with `+webkitgtk1` suffix) once parallel packages are published.

---

## Problem with Phase 1 packaging

Phase 1 publishes binaries named like the Ubuntu packages:

| Artifact | Conflict |
|----------|----------|
| `libwebkitgtk-6.0-4_*.deb` | **Replaces** system package — cannot coexist |
| `libwebkitgtk-6.0-dev_*.deb` | **Replaces** system `-dev` — cannot coexist |
| `libwebkitgtk-6.0.so.4` | Same SONAME/path as system library |

That is fine for a manual “swap the system library” install, but **not** for declaring a dependency in ollmchat: we need packages that install alongside the distro stack.

---

## Naming proposal

Use a single, descriptive infix everywhere: **`webdriver`**.

### Binary packages (Debian/Ubuntu)

| Role | Proposed name | Notes |
|------|---------------|-------|
| WebKitGTK runtime | `libwebkitgtk-6.0-webdriver4` | Parallel to `libwebkitgtk-6.0-4` |
| Thin WebKitGTK dev | `libwebkitgtk-6.0-webdriver-dev` | **pkg-config only** (see below) |

**No parallel JSC packages.** Phase 1 already keeps system JSC (patch comment: “keep system jsc/webdriver”); `build.sh` only publishes `libwebkitgtk-6.0-*` debs. The replacement `libwebkitgtk-6.0-4` links at runtime to stock `libjavascriptcoregtk-6.0.so.1` — same `DT_NEEDED` SONAME as Ubuntu’s build.

Parallel install follows the same rule: ship only the renamed WebKit library + libexec; **do not install** `libjavascriptcoregtk-6.0` from our tree (`-Nlibjavascriptcoregtk-6.0-1`, `-Nlibjavascriptcoregtk-6.0-dev`, `-Nlibjavascriptcoregtk-bin` in gtk4-only rules).

Do **not** ship duplicate headers, `.so` linker stubs, or GIR under `libwebkitgtk-6.0-webdriver-dev` — use system `libwebkitgtk-6.0-dev` / `libjavascriptcoregtk-6.0-dev` for API.

### Why system JSC is enough

| Concern | Answer |
|---------|--------|
| Built in same tree? | Yes — gtk4 cmake still **compiles** JSC internally to link WebKit, but we **do not package** that `.so`. |
| `DT_NEEDED` | `libwebkitgtk-6.0-webdriver.so.4` should need `libjavascriptcoregtk-6.0.so.1` — the **stock SONAME**, not a renamed JSC. |
| ABI match | We build from the **same pinned** `webkit2gtk` source as the series; `ENABLE_WEBDRIVER` touches WebKit only, not JSC’s public ABI. |
| Phase 1 proof | Replacement `libwebkitgtk-6.0-4` + system `libjavascriptcoregtk-6.0-1` already works without shipping our JSC. |

`webkitgtk-6.0-webdriver.pc` uses `Requires: javascriptcoregtk-6.0` (system pkg-config module) — no separate JSC package.

### Shared libraries & SONAMEs

| System | Parallel |
|--------|----------|
| `libwebkitgtk-6.0.so.4` | `libwebkitgtk-6.0-webdriver.so.4` |
| `libjavascriptcoregtk-6.0.so.1` | **unchanged** — system package |

Only WebKit’s **library basename** gains `-webdriver`. JSC stays on the distro stack.

### pkg-config modules

| System | Parallel |
|--------|----------|
| `webkitgtk-6.0` | `webkitgtk-6.0-webdriver` |
| `javascriptcoregtk-6.0` | **unchanged** — system module (referenced from webdriver pc) |
| `webkitgtk-web-process-extension-6.0` | **unchanged** unless a consumer needs a webdriver-specific extension pc later |

Meson: `dependency('webkitgtk-6.0-webdriver')`.

### libexec / private data (critical)

WebKitGTK does not work as “just a `.so`”. The main library spawns helpers from a versioned libexec directory (see upstream `LIBEXEC_INSTALL_DIR` / `PKGLIBDIR` in `Source/WebKit/PlatformGTK.cmake`).

| System | Parallel |
|--------|----------|
| `/usr/libexec/webkitgtk-6.0/` | `/usr/libexec/webkitgtk-6.0-webdriver/` |
| `…/lib/webkitgtk-6.0/` (injected bundle, etc.) | `…/lib/webkitgtk-6.0-webdriver/` |

If we rename only the `.so` but keep system libexec paths, the WebDriver-enabled library would load **stock** `WebKitWebProcess` — wrong behaviour and subtle breakage.

**Recommendation:** drive **both** library names and libexec/data paths from one CMake suffix (e.g. `WEBKITGTK_VARIANT_SUFFIX=-webdriver`), not ad-hoc `dh_install` renames.

### Version suffix on source package

Keep Ubuntu versioning + local suffix for traceability, e.g. `2.52.3-1ubuntu1+webdriver1` (rename from `+webkitgtk1` when parallel packages land).

### Repo / GitHub Release naming

- Release tag: `webkitgtk-webdriver-${version}` (distinct from `webkit2gtk-…` replacement releases).
- Artifact names: `libwebkitgtk-6.0-webdriver4_*.deb`, etc.

## Recommended technical approach

### A. Thin `-dev` packages (preferred)

**Hypothesis:** a small dev package that only provides alternate `.pc` files may be *almost* enough — but only if the **runtime** packages already install renamed libs + libexec under non-conflicting paths. The `.pc` files alone are not sufficient.

**Runtime packages** (from the existing gtk4-only `dpkg-buildpackage` flow, with cmake suffix patch):

- Install renamed `.so*` and helpers.
- **Conflicts/Replaces:** none against `libwebkitgtk-6.0-4` / `libjavascriptcoregtk-6.0-1`.
- **Depends:** normal gtk4/libsoup stack (same as system webkitgtk).

**Thin `-dev` package** (`libwebkitgtk-6.0-webdriver-dev`):

- Ship only: `usr/lib/${DEB_HOST_MULTIARCH}/pkgconfig/webkitgtk-6.0-webdriver.pc`
- **Depends:** `libwebkitgtk-6.0-dev`, `libjavascriptcoregtk-6.0-dev`, `libwebkitgtk-6.0-webdriver4`
- **Does not** ship headers, linker stub, or GIR

**`.pc` file shape** (template — paths filled at package build):

```ini
prefix=/usr
libdir=${prefix}/lib/x86_64-linux-gnu
includedir=${prefix}/include

Name: webkitgtk-6.0-webdriver
Description: WebKitGTK 6.0 with WebDriver interactions (parallel install)
Version: @VERSION@
Requires: gtk4, libsoup-3.0, javascriptcoregtk-6.0
Libs: -L${libdir} -lwebkitgtk-6.0-webdriver
Cflags: -I${includedir}/webkitgtk-6.0
```

`Requires: javascriptcoregtk-6.0` pulls **system** JSC via pkg-config. `Cflags` use system `webkitgtk-6.0` includes; `Libs` point at our library only.

### B. CMake / WebKit build changes (required)

Upstream sets output names from `WEBKITGTK_API_VERSION` (`Source/cmake/OptionsGTK.cmake`, `Source/WebKit/PlatformGTK.cmake`). There is no stock “parallel install suffix” toggle.

**Add a small WebKit cmake patch** (new file under `patches/`, applied in addition to the webdriver `debian/rules` patch):

1. Introduce `WEBKITGTK_VARIANT_SUFFIX` (default empty).
2. When set to `-webdriver`:
   - `WebKit_OUTPUT_NAME` → `webkitgtk-6.0-webdriver` (**WebKit only** — do not rename JSC output; link against stock `libjavascriptcoregtk-6.0.so.1` SONAME).
   - `LIBEXEC_INSTALL_DIR` → `…/webkitgtk-6.0-webdriver` (not `webkitgtk-6.0`).
   - `PKGLIBDIR` → `…/lib/webkitgtk-6.0-webdriver`.
   - **Do not** change `WEBKITGTK_API_VERSION` (stays `6.0`) so **include paths during compile** remain `webkitgtk-6.0/` — matches system headers.
   - **Do not** install in-tree JSC shared libs (`-Nlibjavascriptcoregtk-6.0-*` in debian packaging).
3. Pass from `debian/rules` gtk4 build:

```makefile
EXTRA_CMAKE_ARGUMENTS_GTK4 += -DWEBKITGTK_VARIANT_SUFFIX=-webdriver
```

4. **Do not** install `.pc` files from the cmake build into the renamed modules — generate them in the thin `-dev` step instead (avoids fighting cmake’s `webkitgtk-6.0.pc` generator). Use `dh_install` exclude or skip `install(FILES … .pc)` when suffix is set (patch install rules).

### C. Debian packaging changes (required)

Extend the existing gtk4-only `debian/rules` patch (or add `patches/parallel-install-packaging.patch`) to:

1. **Rename WebKit binary packages** in the gtk4 section of `debian/control` generation (Ubuntu’s rules are templated — mirror how `libwebkitgtk-6.0-4` is produced, but with `-webdriver` infix). **Skip** all `libjavascriptcoregtk-6.0-*` binary packages from install.
2. Adjust `debian/*.install` lists to match new package names.
3. Ensure gtk4-only skips remain (`-Nwebkitgtk-webdriver`, `-Nlibjavascriptcoregtk-bin`, etc.) — we still do not ship a second `WebKitWebDriver` binary; system `webkitgtk-webdriver` stays on 4.1.
4. `dh_makeshlibs` / shlibdeps: new SONAME names must be declared on the new packages (automatic if libs are correctly named).
5. Update `scripts/lib/packaging-checks.sh` with assertions for:
   - parallel package names present in generated `debian/control`;
   - no `Conflicts:` against stock `libwebkitgtk-6.0-4`;
   - cmake suffix marker in patched tree (when pretest unpacks rules only, document that full control check needs `fakeroot debian/rules debian/control`).

### D. Build script / CI changes

| File | Change |
|------|--------|
| `build.sh` | Copy `libwebkitgtk-6.0-webdriver4_*.deb` and `libwebkitgtk-6.0-webdriver-dev_*.deb`; drop or gate Phase 1 artifact names behind `PARALLEL_INSTALL=1`. |
| `SUFFIX` | Default `+webdriver1` (or keep `+webkitgtk1` until cutover). |
| Workflows | Release notes: “install alongside system webkitgtk”; list all four packages. |
| `record-successful-build.sh` | Track new deb glob patterns. |

Pretest remains patch-on-`debian/rules`; add optional pretest that regenerates `debian/control` and runs packaging layout checks.

## ollmchat / Meson consumer integration

Target consumer: `roojs/OLLMchat` → `libocwebkit/meson.build` currently uses:

```meson
dependency('webkitgtk-6.0')
# Vala: --pkg=webkitgtk-6.0
```

### Meson option (recommended)

In ollmchat `meson_options.txt`:

```meson
option(
  'webkit_pc',
  type: 'combo',
  choices: ['webkitgtk-6.0', 'webkitgtk-6.0-webdriver'],
  value: 'webkitgtk-6.0',
  description: 'pkg-config module for WebKitGTK (use webdriver for parallel WebDriver-enabled stack)',
)
```

In `libocwebkit/meson.build` (Linux branch):

```meson
webkit_pc = get_option('webkit_pc')
webkit_dep = dependency(webkit_pc)
# Vala API package stays webkitgtk-6.0 — same vapi/GIR from libwebkitgtk-6.0-dev
ocwebkit_platform_vala_args += ['--pkg=webkitgtk-6.0', '--pkg=atspi-2']
```

`dependency('webkitgtk-6.0-webdriver')` supplies **link flags** from the thin `.pc`; Vala still compiles against **system** `webkitgtk-6.0.vapi`. No duplicate vapi required.

### Runtime

- ollmchat binary should `Depends:` on `libwebkitgtk-6.0-webdriver4` when built with `webkit_pc=webkitgtk-6.0-webdriver` (JSC comes transitively via stock `libjavascriptcoregtk-6.0-1` from `${shlibs:Depends}`).
- `LD_LIBRARY_PATH` is not required if link + `RPATH`/distro shlibs are correct.
- WebDriver automation: still use system `webkitgtk-webdriver` + `WebKitWebDriver`; the **browser** side loads our `libwebkitgtk-6.0-webdriver` when ollmchat (or the embedded WebKit view) is linked against it.

### Documented build example

```bash
# System WebKit (default)
meson setup build

# WebDriver-enabled parallel stack
meson setup build -Dwebkit_pc=webkitgtk-6.0-webdriver
```

CI / dev install:

```bash
sudo apt install ./libwebkitgtk-6.0-webdriver4_*.deb \
                 ./libwebkitgtk-6.0-webdriver-dev_*.deb
# libwebkitgtk-6.0-dev + libjavascriptcoregtk-6.0-1 from archive if not already installed
```

## Alternatives considered

| Approach | Verdict |
|----------|---------|
| **Replace-in-place** (Phase 1) | Simple; **reject** for ollmchat dependency — conflicts with distro packages. |
| **Private prefix** (`/opt/webkitgtk-webdriver`) | Works but breaks distro conventions; harder for `dpkg`/`apt` and Meson defaults. |
| **Change `WEBKITGTK_API_VERSION`** to e.g. `6.0-webdriver` | Renames headers, GIR, vapi paths — **reject**; duplicates entire `-dev` stack. |
| **Post-install `dh_rename` only** | Fragile for SONAME, shlibdeps, and libexec compile-time paths — **reject** as primary strategy. |
| **Environment variable / `LD_PRELOAD`** | No compile-time dep resolution; **reject**. |
| **Thin `.pc` only** | **Insufficient alone** — must pair with renamed runtime libs + libexec. |

## Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Ubuntu `debian/rules` template drift on version chase | Keep series registry + pretest; extend packaging checks for parallel names. |
| WebKit/JSC source pin must match system (`libxml2`, etc.) | Same pinned `webkit2gtk` source as today; we package WebKit only, link to system JSC SONAME. |
| Vala link vs `--pkg` mismatch | Keep `--pkg=webkitgtk-6.0`; use `dependency(webkit_pc)` for linking only. |
| Helper binary mismatch | Suffix drives libexec at **compile** time via `-DPKGLIBEXECDIR=…`. |
| Accidental `Conflicts` in generated control | Explicit packaging check + `dpkg-deb -I` review on first build. |

## LLM notes

- Implement cmake suffix + debian renaming **in this repo**; ollmchat changes are a separate PR there.
- Do not fork WebKit upstream — patch cmake install naming + Ubuntu `debian/rules` only.
- Thin `-dev` is intentional: **runtime** carries the heavy libs; **-dev** carries **only** `.pc` files pointing at system headers.
- Parallel install is **not** optional for ollmchat-as-dependency — Phase 1 replacement packages must not be the long-term dependency target.
