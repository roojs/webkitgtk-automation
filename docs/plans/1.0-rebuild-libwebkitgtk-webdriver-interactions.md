# 1.0 — Rebuild libwebkitgtk-6.0 with WebDriver interactions

**Status:** ⏳ proposed — approve before implement  

**Repo:** this repository (`webkitgtk-automation`)  
**Unblocks:** WebDriver click/sendKeys on Ubuntu GTK4 / libwebkitgtk-6.0  
**Upstream bug:** [WebKit #318171](https://bugs.webkit.org/show_bug.cgi?id=318171)

---

## Purpose

- 🔷 Rebuild Ubuntu **`libwebkitgtk-6.0-4`** so WebDriver mouse/keyboard/wheel work.
- 🔷 Keep system **`webkitgtk-webdriver`** (depends on 4.1); do not ship a second driver.
- 🔷 This repo: clone Ubuntu source → patch → `dpkg-buildpackage` → publish `.deb`s on GitHub.
- ℹ️ Packaging only — not application-side browser automation.

---

## Why

- ℹ️ Ubuntu `debian/rules`: soup3/4.1 gets `-DENABLE_WEBDRIVER=ON`; GTK4/6.0 gets `OFF` → browser-side click/keys return `unsupported operation`.
- 🔷 Fix: GTK4 cmake also gets `-DENABLE_WEBDRIVER=ON` so INTERACTIONS compile into `libwebkitgtk-6.0`.

## Phase A — Build the `.deb`s

**Status:** ⏳  

### A.1 Repo layout (this repo)

- 🔷 ⏳ Add these files at repo root:
  - `patches/enable-webdriver-gtk4.patch` — see A.2
  - `build.sh` — see A.3
  - `.github/workflows/build-resolute.yml` — see A.4
  - `README.md` — how to install the `.deb` + which Ubuntu series

### A.2 Patch file (exact change)

- 🔷 ⏳ `patches/enable-webdriver-gtk4.patch` patches Ubuntu `debian/rules` so **after** the existing “Decide what version of the WebKit WebDriver to build” `ifeq` block, GTK4 is forced on:

**Add** (immediately after that `ifeq` / `else` / `endif` that sets `ENABLE_WEBDRIVER_*` and `WEBDRIVER_DEP_PKG`):

```makefile
# WebKit #318171: compile INTERACTIONS into libwebkitgtk-6.0.
# Installed WebKitWebDriver binary still comes from soup3 (WEBDRIVER_DEP_PKG unchanged).
ifeq ($(ENABLE_GTK4),YES)
	ENABLE_WEBDRIVER_GTK4 = -DENABLE_WEBDRIVER=ON
endif
```

- 🔷 ⏳ Do **not** change `WEBDRIVER_DEP_PKG` (stays `libwebkit2gtk-4.1-0` when `ENABLE_SOUP3=YES`).
- 🔷 ⏳ After first package build, confirm `webkitgtk-webdriver` still Depends on `libwebkit2gtk-4.1-0` and only one `/usr/bin/WebKitWebDriver` is in the packages. If the gtk4 install collides on that binary, exclude `usr/bin/WebKitWebDriver` from the gtk4 install — keep the library change only.

### A.3 `build.sh` (what it must do, in order)

- 🔷 ⏳ Inputs (env or args): `SERIES` (e.g. `plucky`), `SUFFIX` (e.g. `+webkitgtk1`).
- 🔷 ⏳ Steps inside the script:
  1. `sudo apt-get update`
  2. `sudo apt-get install -y devscripts quilt dpkg-dev ubuntu-dev-tools`
  3. Enable `deb-src` for Ubuntu; `sudo apt-get update`
  4. `sudo apt-get build-dep -y webkit2gtk`
  5. `cd` to a work dir; `pull-lp-source webkit2gtk "$SERIES"` (or `apt-get source webkit2gtk`)
  6. `cd` into the unpacked `webkit2gtk-*` tree
  7. Apply `$REPO_ROOT/patches/enable-webdriver-gtk4.patch` with `patch -p1`
  8. `dch -v "$(dpkg-parsechangelog -S Version)${SUFFIX}" "Enable ENABLE_WEBDRIVER for GTK4/libwebkitgtk-6.0 (WebKit #318171)."`
  9. `dpkg-buildpackage -b -us -uc`
  10. Copy `../libwebkitgtk-6.0-4_*.deb` and `../libwebkitgtk-6.0-dev_*.deb` to `$REPO_ROOT/dist/`
- 🔷 ⏳ Script fails if those two `.deb`s are missing.

### A.4 GitHub Actions workflow

- 🔷 ⏳ `.github/workflows/build.yml`:
  1. `workflow_dispatch` with inputs `series` (default `plucky`) and `suffix` (default `+webkitgtk1`)
  2. Runner: amd64 (use a large/self-hosted runner if the org uses one for heavy package builds)
  3. Check out this repo
  4. Run `./build.sh` with those inputs
  5. Upload `dist/*.deb` as workflow artifacts
  6. On success, attach the same `.deb`s to a GitHub Release (tag e.g. `webkit2gtk-${version}${suffix}`)

### A.5 First green run

- 🔷 ⏳ Run the workflow once for the target Ubuntu series.
- 🔷 ⏳ Download `libwebkitgtk-6.0-4_*.deb` from the Release/artifact.

**Smoke:** artifacts exist; `dpkg-deb -I libwebkitgtk-6.0-4_*.deb` shows version ending in `+webkitgtk1` (or chosen suffix).
